## 1. PRODUCT THESIS (read before coding)
1.1 COMMODITIZED: Meta (Andromeda retrieval → GEM embeddings → Lattice ranking) + Google PMax/AI Max do targeting/bidding/placement better than any human. Dozens of AI marketing tools exist. **Creative generation + campaign setup are NOT a moat.**
1.2 THE 4 MOATS (our whole product):
 (1) **Signal quality (crown jewel)** — platforms optimize toward whatever events you feed. SMBs feed junk ("lead submitted"/"conversation started"). We own voice-call outcome + WhatsApp outcome + booking + sale = ground truth of lead quality → CAPI events with value=lead-quality-score → Meta/Google optimize for *our vendor's definition of a good customer*. Flagship loop §11.
 (2) **Attribute-level creative learning + genuine diversity** — Andromeda clusters near-duplicate creatives (Entity-ID clustering) + retrieval-suppresses them; 100 minor variants ≈ 10 distinct concepts. Generate along a diversity matrix (angle×format×visual×hook×headline), tag Creative DNA, learn at the ATTRIBUTE level.
 (3) **Cross-channel orchestration + explainable autonomy** — one brain across Meta+Google+WhatsApp+voice+LP+CRM, trust ladder L0–L4, signed Action Ledger, plain-language "why" per action. Trust is the adoption bottleneck; engineer it as a feature.
 (4) **Cross-tenant learning network** — anonymized priors by industry×geo×objective; a new Ahmedabad salon starts with the posterior of 500 salons. Data network effect.
1.3 POSITIONING: "The platforms decide WHO sees the ad. We decide WHAT to say, HOW MUCH to risk, WHETHER the lead was real, and WHAT to do next — and we prove it with revenue, not clicks."
1.4 DO NOT BUILD: don't fight Advantage+/PMax delivery (feed it better signals+diversity); not a generic horizontal automation tool (n8n exists) — our workflow builder is revenue-domain-specific; no MTA voodoo — deterministic journey truth (click-ID→conversation→call→booking→sale) + honest incrementality.

## 2. NON-NEGOTIABLE DESIGN PRINCIPLES (LAW)
- P1 **Contracts-first**: every service = OpenAPI 3.1 (sync) + AsyncAPI 3 (events) in /contracts + JSON Schemas in /contracts/schemas. CI fails on drift.
- P2 **Event-sourced nervous system**: every business fact = immutable event on the bus (§6). Services own their write models; cross-service ONLY via events. NO service reads another's DB. Ever.
- P3 **Idempotency everywhere**: every external mutation (ad create, budget change, send, CAPI post) carries an idempotency key, exactly-once in effect; consumers replay-safe.
- P4 **Money is sacred**: no path increases spend / launches ads / broadcasts without Budget Governor (§13) + Approval Policy (§17). Structural: connectors accept mutations ONLY from the Action Executor, which only executes SIGNED ActionPlans.
- P5 **Every autonomous action emits an Explanation** `{action,evidence[],expected_effect,confidence,reversible,approval_required,undo_plan}` to the Action Ledger BEFORE execution. No silent actions.
- P6 **Tenant isolation absolute**: tenant_id on every row/event/cache-key/queue-msg. Per-tenant envelope encryption for tokens. Cross-tenant learning only via anonymization (§14.4).
- P7 **Degrade gracefully**: every connector has a circuit breaker + degraded mode (queue & retry, never drop). Predict token expiry; re-auth via WhatsApp before failure.
- P8 **LLM calls routed/budgeted/evaluated**: all model calls via the LLM Gateway (routing by task tier, per-tenant token budgets, response caching, structured-output validation, eval traces). No raw SDK calls in services.
- P9 **Respect platform learning phases**: never edit a live ad in place (resets learning). No optimization edits during active learning unless a kill-guardrail fires.
- P10 **Everything observable**: OpenTelemetry traces across HTTP+bus, RED metrics per service, per-tenant cost meters → Billing.
- P11 **India-first, world-ready**: INR+GST billing, DPDP consent ledger, vernacular first-class, WhatsApp primary surface — all locale logic behind a locale service, no hardcoding.
- P12 **Boring tech, exciting product**: Postgres before exotic DBs. Monorepo. Buy undifferentiated (auth UI, email). Build differentiated (signals, optimization, creative DNA, agents).

## 12. DRAFT/TRASH/PROMOTE BRAIN (Experimentation + Optimizer)
12.1 Objects: Arm=creative×audience-cell×destination; Cell=ad set; Reward=qualified leads (value-weighted by lead_score; Purchase overrides); Cost=spend. Posterior per arm = Gamma–Poisson on qualified-lead rate per ₹ (conjugate, interpretable). Hierarchical priors: arm←creative-DNA attributes←vendor memory←industry benchmark (shrinkage = sane day-1).
12.2 Cadence/learning-phase (HARD): evaluate every 4h; act ≤1×/24h per ad set (except kill-guardrails); never in-place edit live creative/targeting (ships as NEW ads); during learning only guardrail kills, no budget tweaks; flag significant-edit re-learning in Explanation.
12.3 TRASH (guardrails first): G1 runaway spend_today>3×daily_cap_share → pause NOW+alert(any time). G2 zero-q spend≥2.5×target_CPqL AND q_leads=0 → pause CREATIVE(ad), keep set. G3 set-fail spend≥4×target_CPqL AND P(CPqL>target|posterior)>0.85 → pause AD SET. G4 junk leads≥8 AND junk_rate>60%(scores<25) → pause+flag "lead-quality trap". G5 fatigue frequency_7d>2.5(cold) OR CTR≤0.7×7d-peak 3 consecutive days → rotate creative (request siblings, retire ad). G6 policy delivery error/rejection → quarantine+compliance ticket. Every kill emits plain-language + vernacular Explanation.
12.4 PROMOTE: winner n_q≥5 AND CPqL≤0.8×target AND stable ≥3 days AND signal_health=green. Actions: (1) budget +20%/48–72h while MARGINAL CPqL≤target; (2) graduate: clone winning arm into consolidated Advantage+ campaign (don't disturb original until clone exits learning); (3) creative mitosis: 3 siblings sharing winning DNA genes (angle+hook-type) but distinct execution (dodges Entity-ID clustering); (4) audience expansion only AFTER creative expansion. Budget split each tick = Thompson sample, bounded min_explore_share=10%, max_arm_share=40%.
