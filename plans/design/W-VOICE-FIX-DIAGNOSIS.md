## TL;DR — the meta root cause

`droplet_work/agent.py` imports **only** `from prompt import SYSTEM_PROMPT,
GODREJ_FIELDS, build_system_prompt, _gender_of` (agent.py:27). It contains **zero**
references to `voice_kernel` (grep for `voice_kernel|kernel|assemble_outbound|
build_for_call` over agent.py = NO MATCHES). So on the LIVE outbound path:

- The opener is generated by `_llm_opener()` (agent.py:209) → `session.say()`
  (agent.py:884).
- The system prompt is built by `prompt.build_system_prompt(fields)`
  (agent.py:416 / :431).
- The kernel's clean disclosure (`voice_kernel/brain_packs/disclosure.py`, Tier-0,
  `BANNED_PHRASES` block-list) is **NEVER exercised** — `kernel_outbound_enabled()`
  returns `False` by default (outbound.py:52-65), `build_for_call()` returns `None`
  (outbound.py:108-109), and `assemble_outbound_instructions()` returns
  `legacy_render()` when `ik is None` (outbound.py:292-293).

**All four regressions live entirely in `agent.py` + `prompt.py`.** The kernel was
built correct (it already bans the phrase, renders structural Tier-0 disclosure,
fixes prosody) but it was never wired into agent.py — so flipping `KERNEL_OUTBOUND=1`
made things WORSE because the integration is incomplete, NOT because the kernel logic
is wrong. The fix is to make the legacy `prompt.py`/`agent.py` defaults correct (so
the build is good even with the kernel OFF), then wire the kernel as the single
source of the opener + disclosure + prosody when ON.

## BUG 2 — Double greeting (opener spoken, then LLM re-greets on turn 1)

**NOT** "opener + kernel both greet" — the kernel is OFF and never speaks. The
double greeting is **opener (`session.say`) + the system-prompt re-greeting the LLM
on its first reply turn.**

Chain of evidence — call `famit-917861019021-789deb`:
- 15:04:39 — `session.say(opener)` speaks: *"नमस्ते Kunal Kumar जी, मैं Riya बोल रही
  हूँ, AGARO की AI assistant हूँ..."* (agent.py:884)
- 15:05:00 — user: *"बात कर सकती है"* (yes, I can talk)
- 15:05:18 — LLM turn[assistant] RE-GREETS: *"नमस्ते! मैं रिया हूँ, अगारो की तरफ़ से
  कॉल कर रही हूँ। ... हमारे Regal 800W Handheld Vacuum Cleaner के बारे में..."*

**Why the LLM re-greets:**
1. `agent.py:884` `session.say(opener, ..., add_to_chat_ctx=_opener_in_ctx)` —
   `OPENER_IN_CTX` defaults `"1"` (agent.py:883), so the opener IS echoed into chat
   context... but the system prompt STILL actively instructs a fresh greeting:
2. `prompt.py:431-436` `=== OPENER (पहला turn ===` section instructs the model to
   open with *"warm greeting + naam + अपना naam + disclosure + company + product +
   naam confirm"* on its first turn.
3. `prompt.py:308` PROVEN-FLOW step 1: *"WARM GREET + CONFIRM IDENTITY: गर्मजोशी से
   greet ... + {company} का नाम, फिर naam confirm"* — a second instruction to greet.

So on turn 1 the model has TWO standing instructions to greet, and nothing telling
it the opener is already spoken → it greets again.

**The suppression fix EXISTS but is gated OFF on the box:**
- `agent.py:451` `if os.getenv("OPENER_ALREADY_SAID", "0") in ("1","true","True"):`
  → defaults `"0"` → the "तुम पहले ही OPEN कर चुके हो" block (agent.py:452-457) is
  NOT appended → the model never learns it already opened.
- This is the documented FIX A (agent.py:443-450) but it ships default-OFF for
  byte-identity, and it is NOT set in the famit-agent systemd drop-in on the box.

## BUG 3 — Wrong grammar ("aapne call kiya" — inbound phrasing on an outbound call)

The templates are **correct** (outbound first-person):
- `prompt.py:310` FLOW step 2: *"मैंने {product} के बारे में call किया था"* (I called).
- `prompt.py:426-427` *"यह OUTBOUND call है: तुमने caller को {product} के बारे में
  फ़ोन किया है"* (correct framing).
- `prompt.py:93/98` `_opener_verbs()["called"] = "call किया था"` (neutral, fine).

The error is **LLM-generated**, driven by two ambiguous instruction strings that let
the model flip direction:
- `agent.py:240` Groq opener system message: *"कहो कि '{product}' के बारे में call
  किया था"* — the bare *"call किया था"* with no explicit subject lets the model
  attach "aapne" (you), producing inbound grammar *"aapne call kiya"*.
- `agent.py:231-232` the `disc_clause` first-person wording compounds the ambiguity.
- Secondary awkwardness in the LLM's re-greet: *"आपकी बात करने में कुछ समय हो सकता
  है?"* (transcript) — malformed; should be *"क्या आपका थोड़ा समय है?"*.

Root cause: the opener prompt does not PIN the subject as first-person ("मैं/हमने
आपको call किया"), so the temperature-0.5 Groq model occasionally renders the
listener as the caller. The kernel's structural disclosure (disclosure.py:152-157)
fixes this — *"Call ki wajah jaldi bata dena: {purpose}"* states the reason without
a direction-ambiguous "call kiya" verb.

## BUG 4 — Too-variable pace / loudness (and what NEUTRAL should be)

**LIVE path — ElevenLabs TTS in `droplet_work/agent.py:571-580`:**

| Knob | Current (agent.py) | Effect | NEUTRAL target |
|------|--------------------|--------|----------------|
| `stability` | `0.45` (:572, env `EL_STABILITY`) | **PRIMARY cause.** Low stability = high expressive variation → swings in pace AND loudness call-to-call and line-to-line. Comment at :570 literally says "low stability = expressive". | **`0.65`** (consistent, still natural; founder wants neutral/normal, NOT max-expressive). |
| `similarity_boost` | `0.80` (:573, env `EL_SIMILARITY`) | Mostly tone fidelity; secondary effect on variation. | `0.80` (keep). |
| `style` | `0.0` (:574, hardcoded) | Already neutral; style exaggerates delivery + adds 20-50ms. | `0.0` (keep). |
| `use_speaker_boost` | `False` (:575) | Off = no loudness pumping. | `False` (keep). |
| `speed` | `1.08` (:579, env `EL_SPEED`) | 8% faster than default — contributes to "sometimes too fast". | **`1.0`** (true neutral) — or `1.04` if the ~18s slow-opener concern returns. |

The founder says this knob existed in the OLD system and was an easy fix → it is
exactly `EL_STABILITY` + `EL_SPEED`. Both are env-overridable, so the live fix is a
systemd drop-in (`EL_STABILITY=0.65`, `EL_SPEED=1.0`) — no code change needed for
the live path. The branch should also change the in-code DEFAULTS (agent.py:572,
:579) so a fresh deploy is neutral without relying on env.

**KERNEL/Sarvam path (not live for outbound, but harmonize for the cutover):**
- `voice_kernel/speech/prosody.py` prepends SPARSE fillers ("haan"/"achha"/"toh")
  at most 1 per 3 sentences (`_FILLER_EVERY=3`, prosody.py:30) via `apply_prosody()`
  (prosody.py:73). These fillers are what create an UNEVEN perceived rhythm. For the
  founder's "neutral/consistent, do NOT over-vary to sound human" directive, the
  filler injection should be **default-OFF for outbound** (gate it behind a flag),
  leaving punctuation-shaped pauses only.
- `src/agent.py:173` `SARVAM_TTS_PACE` default `1.05` → set `1.0` for neutral.
