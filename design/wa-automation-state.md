# WhatsApp Post-Call Automation — STATE MAP (EXPLORE-1)

> Read-only audit of the LIVE box `famit@168.144.153.145:/opt/famit-agent/` (2026-06-12).
> Goal feature = on call-complete INSTANTLY send the approved post-call WhatsApp template,
> then run a multi-step LLM conversation on the lead's reply. Maps what is built vs the gap.

## 12-LINE MAP (send · after-call-trigger · template · webhook · flags)

1. **SEND (`whatsapp.py`):** `send_whatsapp_async(to, template, params)` → `_meta_template_body` posts a real Meta Cloud API **TEMPLATE** by name with `{{1..n}}` body params (lang from `META_WA_API_VERSION`/cfg `lang`, default `en_US` — note template is **`en`**, see GAP-T). `send_whatsapp_text_async` posts **free-form text** (24h-window only). `meta_configured()`/`is_configured()` true (creds present). `_meta_to` strips leading `+`. **WORKS: can template-send to any number.**
2. **AFTER-CALL TRIGGER:** call-complete hook = `_finalize_call` (caller.py **~1873**, "runs once per completed call"). It already calls **`_wa_ai_followup(...)`** (caller.py ~1932) right after `_send_whatsapp`. So a post-call WhatsApp send **IS wired** — but dormant (flags below).
3. `_wa_ai_followup` (caller.py **1601**): gated by per-campaign **`wa_followup` flag** → if WA configured, drafts Hinglish text via `_wa_draft_followup_text` (one Groq call, call-context-aware) and sends it via **`send_whatsapp_text_async` (FREE-FORM)**, seeds a conversation thread; else falls back to legacy template path `_wa_followup`.
4. **THE CORE GAP (instant cold send):** post-call auto-send uses **free-form text**, which Meta allows **only inside the 24h customer-service window**. A fresh OUTBOUND call does **NOT** open that window (only an inbound WA msg from the lead does) → an instant post-call free-form text to a cold lead will be **rejected by Meta**. The approved **template** path is the correct cold-send vehicle but `_wa_ai_followup` does **not** send the template instantly — it only uses `wa_template_*` campaign-field names via the legacy fallback, and those fields are **blank**.
5. **TEMPLATE (approved, live):** **`post_call_followup`** — **APPROVED · MARKETING · en**. Body: `"Hi {{1}}, thanks for taking our call about {{2}}. Reply here if you have questions or want to take the next step."` → **2 vars: {{1}}=lead name, {{2}}=product/enquiry**. Buttons: 2 QUICK_REPLY (`Yes, tell me more`, `Not Interested`). (Only other approved template = `hello_world`.) **The template name `post_call_followup` is NOT referenced anywhere in caller.py** — no campaign field is set to it.
6. **INBOUND WEBHOOK — GET verify** (caller.py **4361** `/whatsapp/inbound`, no auth): Meta hub-challenge handshake, token **`evsaivoiceagent`** (env `META_WA_VERIFY_TOKEN`). Endpoint VERIFIED earlier. **WORKS.**
7. **INBOUND WEBHOOK — POST receive** (caller.py **4415**): verifies `X-Hub-Signature-256` (app-secret HMAC), parses messages via `_parse_meta_inbound`, always returns fast 200. **Parses text + button taps + interactive button_reply/list_reply** into `{phone,text}`. **WORKS.**
8. **INBOUND ROUTING (the reply brain):** POST → `_wa_handle_inbound` (caller.py **1543**): resolves lead/campaign/tenant by phone, maintains a per-contact **thread** (`var/wa_threads/<digits>.json`), applies opt-out (STOP/band-karo → suppress+flip+webhook), human-handoff words, and `WA_MAX_TURNS=12` cap. If still in convo → **`_wa_reply_text`** (caller.py **1518**) = ONE Groq call with **system brain (agent/company/product/summary) + last 10 thread turns + incoming** → sends reply via `send_whatsapp_text_async`. **MULTI-STEP CONTEXT-RICH REPLY BRAIN EXISTS and WORKS** (free-form, valid because the lead's inbound opened the 24h window).
9. **NOT routed to ai_manager / workforce:** the inbound reply brain is the **self-contained local `_wa_reply_text` Groq helper**, NOT the `ai_manager/`/`workforce/` LLM command service (grep: zero wa→ai_manager wiring). It cannot take business actions (book/schedule) — only converses + flags `needs_human`. Gap if richer action-taking is wanted.
10. **FLAGS (env `/opt/famit-agent/.env`):** `FEATURE_WHATSAPP=1` ✓, `FEATURE_WHATSAPP_BUILDER=1` ✓, Meta creds present ✓. **No `WA_AUTO*` flag** — the auto-send gate is the **per-campaign `fields.wa_followup`** boolean (default OFF). **EVERY campaign on the box has `wa_followup=False` and blank `wa_template_*`** → the after-call auto-send is **wired but fires on zero campaigns today**.
11. **MANUAL FALLBACK (`/whatsapp/send`, caller.py 4321):** founder's working path — manager+/admin form-POST `to/template/params`, routes text vs template. `wa_log.json` shows real `sent:200` (10-Jun) but also recent `sent:404` (11-Jun) = template-name/param mismatches on manual sends. **WORKS but flaky on bad template names.** Threads currently 0; no auto-followup ever fired (all gates OFF).
12. **SERVICES (regression baseline):** `famit-caller`, `famit-agent`, `famit-bridge` all **active**. Live outbound earner (`agent.py`) **untouched** by the WA path (WA is fire-and-forget, never blocks/raises into the call loop).

## WHAT WORKS vs THE GAP (build targets)

**WORKS today:** template-send-by-name to any number (`send_whatsapp_async`); approved `post_call_followup` template (2 vars + buttons); inbound webhook GET-verify + POST-receive (sig-checked, parses text+buttons); per-contact threaded **multi-turn LLM reply** on inbound (`_wa_reply_text`, campaign+history grounded); opt-out/handoff/turn-cap guards; the after-call hook **already calls** `_wa_ai_followup`; per-message logging; live-path safety.

**THE GAP (to deliver "INSTANT approved-template send on call-complete"):**
- **G1 — instant cold send uses the TEMPLATE, not free-form.** `_wa_ai_followup` must, for a fresh post-call (no open 24h window), send the **approved `post_call_followup` template** with params `[name, product/enquiry]` via `send_whatsapp_async` — not free-form text (which Meta rejects cold). Keep free-form only when a window is already open.
- **G2 — wire the template name.** Nothing references `post_call_followup`; the auto-send falls back to blank `wa_template_*` fields. Need a default/config so the approved template name + its 2-var mapping is used (env default or per-campaign field auto-populated).
- **G3 — turn the gate ON.** `fields.wa_followup` is False on all campaigns and there is no global flag. Need either a global `WA_AUTO_FOLLOWUP=1` env or set `wa_followup=true` per campaign — else the wired path never fires.
- **G4 (language)** template is **`en`** but send cfg lang likely defaults `en_US`/`hi` → must pass `language.code=en` for `post_call_followup` or Meta 404s (matches the recent manual `sent:404`).
- **G5 (optional, richer)** inbound reply brain is local Groq, not the `ai_manager/workforce` action-taking service — fine for conversation; wire to workforce only if replies must execute actions (booking).
